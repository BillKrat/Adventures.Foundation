## Repo overview

Owner: Claude. Reusable .NET class libraries for the `Adventures.*` family, extracted from `ai-research-blog` on 2026-09-19. `Adventures.*` means reusable across products; `<Product>.*` means specific to one. Package descriptions, consuming and publishing instructions: `README.md`.

- **Libraries (`src/`, reference graph pinned by `test/Adventures.Architecture.Tests`; plan: `ai-research-blog/docs/Claude-architecture-reference.md`):** `Adventures.Common` and `Adventures.Ioc` (base, diagnostics, DI scan), `Adventures.Entities` (storage-agnostic dynamic entity model; `IEntityBll`, `IEntityDal` and `IEntityRepository<T>`; security model, rights, diagnostics entities), `Adventures.Security` (framework-free core: JWT, OAuth2 client credentials, hashing; ASP.NET wiring in `Adventures.Security.AspNetCore`), `Adventures.Identity` (+ `.Postgres` credential vault), `Adventures.Data` (contracts only) with `Adventures.Data.Postgres` and `Adventures.Data.NQuad` (N-Quad store, `NQuadEntityRepository<T>`), `Adventures.MEF` (plug-in seam), `Adventures.Collaboration`, `Adventures.Blog` (+ `.Postgres`, `.Legacy`, `.WebApi`), `Adventures.Data.Sql`, and `Adventures.WebApi` (controller bases, correlation, diagnostics, request hardening). Each feature is wired by one `AddXxx()` call. Matching xUnit projects in `test/`.
- **Build and test:** `dotnet build Adventures.Foundation.slnx`, `dotnet test`. `Adventures.Data.NQuad.Tests` also has live-Postgres tests that need the `ConnectionStrings:Postgres` user-secret; the rest run offline.
- **Publish:** pushing a `v*` tag runs `publish.yml` to nuget.org via Trusted Publishing (no stored API key). `build.yml` builds on push and PR to `main`.
- **Consumer:** `ai-research-blog` references these projects by relative path from its `.slnx`, not as NuGet packages. Keep the two repos on matching branches.
- **Hard rule:** user passwords and machine secrets deliberately use different hashers (`PasswordHasher` vs `ClientSecretHasher`). Do not unify them.
- **License (2026-10-24):** BUSL-1.1 like `ai-research-blog` (packages declare `BUSL-1.1`); earlier versions and already-published NuGet packages stay MIT. Decision and open items: `ai-research-blog/docs/Claude-decision-2026-10-licensing.md`.
- **No audit trail, no regulated use (owner, 2026-10-29):** the software keeps no audit trail and must never be described as having one, and regulated use of any kind is outside the licence (NOTICE, "Regulatory disclaimer and field of use"; Additional Use Grant condition 3). Do not add audit features, compliance claims or regulated-field marketing. Decision: `ai-research-blog/docs/Claude-decision-2026-10-regulated-use.md`.
- **Engineering standard (human, 2026-10-24):** security, best practices and patterns come first, backed by test-driven development. Write the failing test first; run the full suite before every commit; nothing merges with a failing test; a security-relevant change names the finding or threat it addresses; a commit message or stamp claims only what was verified ("reviewed" means a review ran, "passed" means the tests passed).
- **Status (2026-10-24):** `main` is a single baseline commit under BUSL-1.1 (licensor Diane Kratochvil, doing business as Adventures On The Edge; decision in `ai-research-blog/docs/Claude-decision-2026-10-licensing.md`). It carries everything the live `ai-research-blog` runs, including the collaboration model for developers and researchers described in that repo's AGENTS.md. `ai-research-blog` uses the same branch names; keep the two in step. The seed triad (`seed.nq` here, plus `mock-data.txt` and `validated.csv` in `poc`) must stay in sync.
