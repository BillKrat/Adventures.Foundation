# Contributing

Adventures.Foundation is developed by a very small team. We do **not** accept
unsolicited code contributions (pull requests) by default.

## What is welcome

- **Issues**: bug reports, security reports, and ideas. Security problems
  should be reported privately to the maintainer, not in a public issue.
- **Discussion**: questions about using the work under its licence.

## If you want to contribute code

Contributions are accepted only when all of these happen, in order:

1. **Propose first.** Open an issue describing the change and why it matters.
   Do not write a large change before we agree it is wanted.
2. **Review.** A maintainer and an AI-assisted review examine the change for
   correctness, security, fit, and licence cleanliness. The bar is high and
   most proposals will not pass it.
3. **Sign the CLA.** You must agree to [CLA.md](CLA.md) before any code is
   merged. It lets the project license your contribution under the project
   licence and under commercial licences.
4. **Significant contributions get a written agreement.** If a change is
   significant (see section 5 of the CLA), we agree in writing, before merge,
   how you will be credited and compensated. Without a signed agreement, a
   significant change is not merged.
5. **Disclose AI assistance.** Say if any part was generated by an AI tool.
